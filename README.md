# 이커머스 고객 분석 프로젝트

상품·거래 데이터를 정제하고 이미지·텍스트 피처와 RFM(Recency, Frequency, Monetary)을 활용해 단골 고객을 분석하는 학습 프로젝트입니다.

현재 **전체 데이터 기본 탐색, 대표 이미지 준비, 전처리 기준 수립, 전처리 파이프라인 구현과 실행**까지 완료했습니다. 고객 세분화와 비즈니스 전략 도출은 후속 단계입니다.

## 진행 현황

| 단계 | 상태 | 결과 |
|---|---|---|
| 원본 CSV 확보 | 완료 | 12,180행, 13개 컬럼 |
| 상품 대표 이미지 준비 | 완료 | 46개 상품명에 합성 스케치 46개 연결 |
| 전체 데이터 기본 탐색 | 완료 | 코드·출력·단계별 설명을 포함한 노트북 |
| 전처리 기준 문서화 | 완료 | 날짜·국가·결제·결측·주문 상태·오류 처리 기준 |
| 전처리 구현 및 실행 | 완료 | 정제 CSV, 확인 필요 CSV, 처리 요약 JSON |
| 검증 | 완료 | 자동 검증 테스트 7개 통과, Claude 리뷰 1회 후 직접 검증·반영 |
| 노트북 전처리 전후 비교 | 예정 | 기존 노트북은 원본 탐색 결과이며 정제 전후 비교는 미추가 |
| 이미지·텍스트 피처 생성 | 예정 | 이미지 평균·표준편차, 상품명 길이 등 |
| IQR 분석과 통계·시각화 | 일부 구현 | IQR 탐지 메서드 구현, 실제 분석·전후 분포 비교·필수 차트 6종은 예정 |
| RFM 고객 세분화 | 일부 구현 | 원시 R/F/M 계산 메서드 구현, 점수·고객군·차트·리포트는 예정 |
| 비즈니스 인사이트 | 예정 | 실제 분석 근거·실행 방안·검증 방법을 갖춘 인사이트 3개 이상 |

원본 기준 고유 고객은 3,374명, 고유 상품명은 46개입니다. 주문 ID 중복이 포함되어 있으므로 행 수를 고유 주문 수와 동일하게 취급하지 않습니다.

데이터셋 다운로드 URL·제공자·이용 라이선스는 현재 저장소 문서에 확인된 정보가 없습니다. 제출·공유 전에 출처와 이용 조건을 확인해 기록해야 합니다. 실제 데이터인지 합성 거래인지도 출처 근거 없이 단정하지 않습니다.

### 상품 이미지

[`dataset/raw/images/`](dataset/raw/images/)에는 내장 이미지 생성 도구로 만든 **흰 배경의 단순한 흑백 대표 스케치 46개**가 있습니다. 처음 100행에서 확인한 41개 품목을 생성하고, 전체 데이터 탐색에서 발견한 누락 5개 품목을 추가했습니다.

- [`image_mapping.csv`](dataset/raw/images/image_mapping.csv)의 `Product_Name`으로 이미지 경로를 연결합니다.
- 실제 판매 상품 사진이 아니며 브랜드·모델과 일치하지 않습니다. 같은 상품명이 실제 같은 모델임을 보장하지 않습니다.
- 이미지 통계는 합성 스케치의 특성을 나타내므로 실제 상품 외관과 구매 행동의 관계를 설명하는 근거로 사용하지 않습니다.
- 생성 프롬프트와 설명은 [이미지 README](dataset/raw/images/README.txt)에 있습니다.

## 실행 방법

현재 검증 환경은 Python 3.14이며 분석·노트북 도구 버전은 [`requirements.txt`](requirements.txt)에 고정했습니다. 미션의 Python 최소 버전과 별개로, 현재 고정된 패키지의 호환성을 위해 Python 3.14 환경을 권장합니다.

프로젝트 루트에서 실행합니다. 기존 `.venv`가 있으면 환경 생성은 생략합니다.

```bash
python3.14 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python src/pipeline.py
```

입력·출력 경로를 지정할 수도 있습니다.

```bash
.venv/bin/python src/pipeline.py --input dataset/raw/csv/ecommerce_retail_transactions_raw.csv --output-dir dataset/processed
```

원본은 변경하지 않습니다. 같은 출력 디렉터리로 재실행하면 기존 정제 결과 3개 파일을 갱신합니다. 프로젝트의 원본 데이터 디렉터리 및 그 하위 경로, 입력 CSV가 있는 디렉터리를 출력 위치로 지정하는 것은 거부합니다. 입력 CSV를 덮어쓰는 경로도 거부합니다.

검증 실행:

```bash
.venv/bin/python scripts/check_pipeline.py
```

VS Code 등 IDE에서 [`notebooks/analysis_report.ipynb`](notebooks/analysis_report.ipynb)를 열고 `.venv`를 커널로 선택해 위에서부터 실행할 수 있습니다. 노트북 실행 위치는 프로젝트 루트 또는 그 하위 폴더여야 합니다. 별도의 Jupyter 웹 서버 설치 없이 IDE의 노트북 기능을 사용할 수 있습니다.

## 전처리 구현

[`src/pipeline.py`](src/pipeline.py)의 `DataAnalyzer` 클래스가 다음 흐름을 수행합니다.

1. 원본을 문자열로 읽고 필수 컬럼과 빈 데이터를 확인합니다.
2. 공백 정리 기준으로 완전 중복을 제거합니다. 식별자는 문자열로 유지합니다.
3. 국가·결제 수단·주문 상태를 정규화합니다.
4. 명시적 날짜 형식과 합의한 국가별 가정으로 날짜를 변환하고 확인 항목을 기록합니다.
5. 숫자·범위를 검사하고 도시·할인율 결측을 처리합니다.
6. 추정 금액을 계산하고 매출·RFM 공통 분석 대상을 표시합니다.
7. 정제 결과·확인 목록·처리 집계를 저장합니다.

원본 컬럼 값은 보존하고 정규화·숫자 변환·대치 결과는 별도 파생 컬럼에 기록합니다. 자세한 정책은 [`docs/preprocessing_policy.md`](docs/preprocessing_policy.md)를 참고하세요.

### 핵심 처리 기준

| 항목 | 처리 |
|---|---|
| 국가 | 미국 표기 변형은 `USA`로 통일하고 다른 국가는 각각 유지 |
| 결제 수단 | 신용카드 표기를 `CREDIT_Card`로 통일하고 다른 결제 수단과 구분 |
| 평점 | 결측 유지, 유효한 관측값으로만 통계 계산 |
| 배송 도시 | 결측을 `Unknown`으로 표시 |
| 할인율 | 원본 결측에만 상품별 중앙값 → 카테고리 중앙값 → 전체 중앙값 적용, 대치 여부·단계 기록 |
| 숫자 오류 | 무한대·변환 실패·범위 위반은 확인 목록에 기록. 오류 할인율을 결측 대치로 숨기지 않음 |
| 주문 상태 | 유효한 `Delivered` 거래만 매출·RFM 공통 대상에 포함. 다른 상태는 정제 데이터에 보존 |
| 중복 | 전체 컬럼이 같은 추가 중복만 제거. 같은 주문 ID만으로 삭제하지 않음 |
| 금액 | 수량 × 단가 × (1 − 분석용 할인율 / 100). 실제 결제액을 확인한 값이 아닌 추정치 |
| IQR | 유효값에 대한 이상치 탐지 제공. 탐지만으로 자동 삭제하지 않음 |

`calculate_rfm()`은 대상 거래의 최근 구매 경과일·고유 주문 수·추정 할인 후 금액 합계를 계산합니다. 기본 기준일은 대상 거래의 마지막 거래일이며, 해당 날짜의 구매는 Recency가 0일입니다. CLI 전처리 실행 시 RFM 파일은 자동 생성하지 않습니다.

### 날짜 해석 가정과 한계

연도가 앞인 날짜와 영문 월이 있는 날짜는 명시된 형식으로 읽습니다. 숫자 날짜가 월/일·일/월 모두 가능하면서 서로 다를 때에는 다음 **프로젝트 가정**을 적용합니다.

- `USA`: 월/일/연도
- `UK`, `Canada`, `Australia`, `Germany`, `India`, `UAE`: 일/월/연도

이 규칙은 사용자 합의에 따른 가정이며, 데이터 출처에서 확인한 형식이나 국가별 유일한 표준이 아닙니다. 원본과 가정 적용 표시를 유지하며 출력은 `YYYY-MM-DD` 형식으로 통일합니다.

한쪽 해석만 유효하지만 국가 규칙과 반대인 날짜는 후보를 보존하되 확인 필요로 처리하고 날짜 기반 분석에서 보류합니다. 예를 들어 `USA`의 `19/08/2025`는 후보 날짜가 `2025-08-19`여도 국가 규칙 충돌입니다.

실제 검사에서는 국가와 관계없이 한쪽 해석만 유효한 숫자 날짜 중 `-`는 월/일만 유효한 1,467행, `/`는 일/월만 유효한 1,447행이 관측됐으며 반대 패턴은 관측되지 않았습니다. 날짜 형식이 구분자에 연결됐을 가능성이 있으므로 **현재 국가 가정으로 계산한 Recency·월별 매출·고객군은 추후 확인 또는 다른 시나리오와의 비교가 필요합니다.** 승인된 규칙을 자동 변경하지는 않습니다.

### 결과 파일 읽는 방법

| 파일 | 내용 |
|---|---|
| [`transactions_cleaned.csv`](dataset/processed/transactions_cleaned.csv) | 중복 제거 후 모든 주문 상태와 원본·파생 컬럼. 분석 대상 표시 포함 |
| [`review_required.csv`](dataset/processed/review_required.csv) | 확인할 항목마다 한 행. 원본 레코드 번호·주문 ID·컬럼·원본값·사유·날짜 후보 포함 |
| [`preprocessing_summary.json`](dataset/processed/preprocessing_summary.json) | 처리 건수, 날짜 상태, 대치 단계, 상태별 대상 수, 국가·구분자 교차 집계 |

주요 컬럼:

- `analysis_eligible`: 매출·RFM 공통 분석 대상 여부.
- `analysis_exclusion_reasons`: 제외 사유를 세미콜론으로 연결한 값.
- `row_needs_review`: 어떤 컬럼이든 확인 항목이 있는지 표시. 분석에 필수가 아닌 컬럼 문제만 있으면 분석 대상일 수도 있습니다.
- `source_csv_row`: 원본의 헤더 포함 CSV 레코드 번호. 셀 안의 줄바꿈이 있다면 텍스트 편집기의 물리적 줄 번호와 다를 수 있습니다.
- `date_parse_status`, `date_needs_review`, `date_country_assumption_used`: 날짜 처리 상태·확인 필요 여부·가정 적용 여부.
- `candidate_mdy`, `candidate_dmy`: 숫자 날짜를 월/일과 일/월로 읽은 후보.
- `discount_was_missing`, `discount_fill_source`: 할인율 원본 결측 여부와 대치 출처.
- `amount_estimated_usd`: 관측 또는 대치 할인율을 적용한 추정 금액. 실제 결제액·회계상 확정 매출이 아닙니다.

## 검증 범위

[`scripts/check_pipeline.py`](scripts/check_pipeline.py)의 테스트 7개에서 다음을 확인했습니다.

- 국가별 날짜 가정, 규칙 충돌 보류, 동일 월·일, 잘못된 날짜, 날짜 결측·미지원 형식
- 상품·카테고리·전체 중앙값 대치, 근거가 전혀 없는 할인율의 미해결 처리
- 중복 제거, 원시 RFM 계산, 원본 보존, 재실행과 원본 덮어쓰기 방지
- 확인 CSV의 날짜 후보, 국가·결제 미매핑, 주문·고객 충돌, 미등록 상태 집계
- IQR의 무한대·오류값 제외, CLI 출력 경로 처리, 실제 데이터 집계 불변식

Claude 리뷰는 저장소의 `AGENTS.md` 절차에 따라 1회 진행했고 지적을 직접 확인해 필요한 수정을 반영했습니다. 날짜 가정과 관측 패턴 차이는 미해결 한계로 문서화했습니다.
