# 이커머스 데이터 전처리 기준

작성일: 2026-11-25

이 문서는 전체 데이터 기본 탐색 결과와 사용자 합의에 따른 전처리 기준이다. `src/pipeline.py`의 `DataAnalyzer`로 구현했으며, 실행 방법과 결과 파일은 10절에 기록한다. 날짜의 월·일 순서는 배송 국가별 형식을 따른다는 사용자 승인 가정으로 해석한다. 규칙으로 처리할 수 없는 값은 확인 필요 항목으로 보존한다.

## 1. 데이터와 원본 보존

- 거래 원본: `dataset/raw/csv/ecommerce_retail_transactions_raw.csv`
- 이미지 매핑: `dataset/raw/images/image_mapping.csv`
- 탐색 노트북: `notebooks/analysis_report.ipynb`
- 탐색 결과: 12,180행, 13개 컬럼, 고유 고객 3,374명, 고유 상품명 46개.
- 원본 CSV·이미지를 덮어쓰지 않는다. 전처리는 복사본에서 수행하고 정제 데이터는 원본과 분리한다.
- 고객·주문 식별자는 문자열로 유지한다. 문자열 앞뒤 공백을 정리하고 공백만 있는 값은 결측으로 취급한다.
- 원본 값, 대치 여부, 오류·보류 사유를 추적할 수 있도록 기록한다. 아래 신규 컬럼명은 구현 시 사용할 기준 이름이다.

## 2. 날짜: 배송 국가별 해석 가정 적용

### 채택한 가정과 적용 범위

사용자 합의에 따라 **날짜는 배송 국가의 표기 관행을 따른다**고 가정한다. 아래 표는 이번 프로젝트의 해석 규칙이며 국가별 유일한 표준이거나 데이터 출처에서 검증된 사실이라는 뜻은 아니다. 특히 캐나다처럼 여러 표기가 사용될 수 있는 국가에도 프로젝트 규칙을 일관되게 적용한다.

| 정규화한 배송 국가 | 월·일이 모호한 숫자 날짜의 해석 |
|---|---|
| `USA` | 월/일/연도 (`MM-DD-YYYY` 또는 `MM/DD/YYYY`) |
| `UK`, `Canada`, `Australia`, `Germany`, `India`, `UAE` | 일/월/연도 (`DD-MM-YYYY` 또는 `DD/MM/YYYY`) |

국가를 먼저 3절 기준으로 정규화한다. `-`와 `/`는 구분자이며 그 자체로 월·일 순서를 결정하지 않는다.

### 처리 우선순위

1. 원본 `Order_Date`를 보존하고 별도 `order_date_parsed`에 변환한다. 분석 중에는 날짜 자료형, CSV 출력에는 `YYYY-MM-DD`를 사용한다.
2. 연도가 앞인 `2026-04-03`, `2025/11/05`는 연-월-일로 읽는다. 영문 월이 있는 `17 Jun 2024`도 명시적 형식으로 변환한다. 이 날짜들에는 국가별 숫자 순서 규칙을 적용하지 않는다.
3. 연도가 뒤인 숫자 날짜는 월/일과 일/월을 각각 검사한다. 한쪽만 달력상 유효하면 그 날짜를 사용하며, 두 해석이 같은 경우도 해당 날짜를 사용한다.
4. 두 해석이 모두 유효하면서 서로 다를 때에만 위 국가별 규칙으로 하나를 선택한다. `date_parse_status=country_assumed`와 `date_country_assumption_used=True`로 가정 적용을 표시한다.
5. 한쪽만 유효하지만 국가별 규칙과 반대 순서인 경우에는 유효한 날짜를 후보로 보존하고 `country_format_conflict`로 확인 필요 목록에 기록한다. 예: `USA`의 `19/08/2025`는 `2025-08-19`로 읽을 수 있으나 월/일 가정과 충돌한다. 원본에 다른 날짜 근거가 없는 경우 최종 RFM·월별 매출에서는 확인 전까지 보류한다.
6. 지원하지 않는 형식, 달력상 불가능한 날짜, 날짜 결측, 국가를 정하지 못한 모호한 날짜는 임의로 추정하지 않고 확인 필요 항목으로 보존한다. 미지원·누락 국가라도 날짜 자체가 명확하면 변환할 수 있으며, 국가 표기 문제는 별도로 기록한다.

### 실제 예시

| 국가 | 원본 날짜 | 결과 | 판정 |
|---|---|---|---|
| `USA` | `11-09-2024` | `2024-11-09` | 국가 가정 적용 |
| `Australia` | `06-05-2024` | `2024-05-06` | 국가 가정 적용 |
| `Canada` | `12-09-2024` | `2024-09-12` | 국가 가정 적용 |
| `Germany` | `02/06/2025` | `2025-06-02` | 국가 가정 적용 |
| 어느 국가든 | `05-05-2024` | `2024-05-05` | 두 해석이 동일 |
| `USA` | `19/08/2025` | 후보 `2025-08-19` | 국가 규칙 충돌, 확인 필요 |

기존 탐색에서 월·일이 모호한 날짜는 1,802행이었다. 이 수치는 전처리 전 탐색 결과이며 국가 가정 적용 후 미해결 건수와 다르다. 기존 노트북의 구분자별 참고 가정은 최종 전처리 규칙으로 사용하지 않는다.

### 확인 필요 항목의 보존과 분석 사용

- 행을 삭제하거나 임의의 기본 날짜로 채우지 않는다. 원본 CSV 행 번호, 주문 ID, 원본 날짜, 원본/정규화 국가, 가능한 해석, 적용 규칙, 확인 사유를 기록한다.
- `date_parse_status`와 `date_needs_review`로 처리 결과 및 확인 필요 여부를 구분한다. 국가 규칙 충돌의 경우 후보 날짜가 있어도 `date_needs_review=True`로 표시한다.
- 변환 불가 사유는 `missing_date`, `invalid_date`, `unsupported_format`, `ambiguous_country_unmapped` 등으로 구분한다. 국가 규칙 충돌은 `country_format_conflict`로 별도 집계한다.
- 전처리 구현 시 `dataset/processed/review_required.csv`에 확인 필요 항목을 별도 저장한다. 다른 컬럼의 미해결 문제도 컬럼명과 사유를 구분해 이 목록에 기록한다. 이 파일은 전처리 실행 시 생성한다.
- 최종 날짜 기반 분석에는 날짜 변환에 성공하고 확인 필요 상태가 아닌 거래를 사용한다. 보류로 빠진 거래·고객 수와 결과 편향 가능성을 보고한다. 국가 가정으로 해석한 날짜는 별도 표시를 유지한 채 분석에 포함한다.
- 출처 설명이나 생성 코드에서 실제 형식이 확인되면 확인 사유와 해결 근거를 기록하고 보류 거래를 재처리한다. 해석 결과를 확정 사실로 표현하지 않는다.
- 최종 RFM 대상의 유효 완료 구매 중 최종 거래일을 기준일로 사용한다. Recency는 기준일과 마지막 완료 구매일의 날짜 차이이며 당일 구매는 0일이다.
- 보고서에는 국가별 날짜 해석 가정, 가정 적용 건수, 충돌·미해결 건수 및 해당 가정이 Recency·월별 매출·고객군에 영향을 줄 수 있음을 명시한다.

## 5. 결측치 처리

| 컬럼 | 원본 결측 수 | 확정 처리 |
|---|---:|---|
| `Customer_Rating` | 6,150 | 결측 유지. 미평가를 0점이나 평균 점수로 바꾸지 않는다. |
| `Shipping_City` | 502 | 분석용 값에 `Unknown`을 사용한다. 국가나 고객의 다른 주문으로 도시를 추정하지 않는다. |
| `Discount_Percent` | 735 | 원본을 보존하고 분석용 할인율을 그룹별 중앙값으로 대치한다. |

### 평점

- 배송 완료 외 상태 5,507행은 전부 평점이 없다. 배송 완료 주문에서도 643행의 평점이 없다.
- 평점 통계는 유효한 관측값만 사용하고 분석 대상 수·유효 평점 수·응답률을 함께 표시한다.
- 미평가를 만족이나 불만족으로 해석하지 않는다. 범위 밖 평점은 오류 후보로 따로 기록한다.

### 할인율

- `discount_was_missing`에 원본 결측 여부를 기록하고 `discount_percent_filled`에 대치 결과를 저장한다.
- 유효 범위 0~100%의 관측값으로 같은 상품의 중앙값을 구한다. 값이 없으면 같은 카테고리 중앙값, 그래도 없으면 전체 중앙값을 사용한다.
- 대치 통계는 중복을 제거한 거래에서 계산하고 어떤 단계로 채웠는지 기록한다. 전체 유효값도 없으면 추정하지 않고 미해결로 보고한다.
- 범위 밖 할인율은 원본 결측과 구분한 오류 후보로 기록하며, 오류값을 대치 통계에 포함하지 않는다.
- `0%`는 관측된 할인 없음이며, 결측과 구분한다. 대치값은 실제 적용 할인율이 아니다.

### 금액과 해석

- 할인 전 거래금액: `Quantity × Unit_Price_USD`.
- 추정 할인 후 거래금액: `Quantity × Unit_Price_USD × (1 - discount_percent_filled / 100)`.
- 이 데이터에는 실제 결제액·환불액 확인 컬럼이 없으므로 추정 할인 후 금액을 실제 결제액이나 회계상 확정 매출로 부르지 않는다.
- RFM의 Monetary에는 추정 할인 후 거래금액 합계를 사용하되 추정치임을 명시한다. 고객별 대치가 포함된 거래 수와 금액 비중을 함께 확인한다.
- 할인 전 금액 기준과 비교하여 고객군이 크게 바뀌는지 확인한다. 미해결 할인율이나 오류값이 남은 거래는 금액 계산을 보류하고 건수를 보고한다.

## 6. 주문 상태와 매출·RFM 대상

모든 상태를 정제 데이터에 보존하고, 분석용 필터로 대상 거래를 구분한다.

| 상태 | 완료 구매 금액·RFM 포함 | 별도 활용 |
|---|---|---|
| `Delivered` | 유효성 검사 통과 시 포함 | 완료 구매 분석 |
| `Cancelled` | 제외 | 취소 현황 |
| `Returned` | 제외 | 반품 현황 |
| `Pending` | 제외 | 미완료 주문 현황 |
| `Shipped` | 우선 제외 | 배송 중 주문 현황 |

- 이는 이번 과제의 완료 구매 기준이다. 상태별 현황은 특정 시점의 관측 상태이며, 배송 중·대기 주문을 이탈이나 취소로 간주하지 않는다.
- 환불액·부분 반품 정보가 없으므로 정확한 순매출은 계산하지 않는다. 반품 제외 금액을 확정 순매출로 표현하지 않는다.
- 완료 구매가 없는 고객은 구매 기반 RFM에서 제외하고 별도 집계한다.
- Recency는 마지막 완료 구매일부터 기준일까지의 일수, Frequency는 고객별 고유 완료 주문 수, Monetary는 대상 거래의 추정 할인 후 금액 합계로 계산한다.
- 날짜·식별자·수량·단가·할인율 검사에 통과한 공통 거래 집합으로 R/F/M을 계산한다. 오류 때문에 제외된 거래와 고객 수를 보고한다.

## 7. 중복과 숫자 오류 후보

- 원본의 완전 중복 추가 행은 180개다. 공백 정리 후 완전 중복을 제외하면 반복 주문 ID와 고객 충돌 주문 ID는 각각 0개다.
- 전처리 복사본에서 전체 컬럼이 같은 완전 중복은 첫 행만 유지한다. 주문 ID가 같다는 이유만으로 서로 다른 상품 행을 삭제하지 않는다.
- 수량 0 이하 후보는 192행이다. 음수를 자동으로 양수로 바꾸지 않는다. 반품 표현 방식과 상태를 확인하고 완료 구매 분석에서 부적합한 값을 제외한다.
- 수량은 양의 정수, 단가는 양수여야 완료 구매 금액에 사용한다. 숫자 변환 실패와 유효 범위 위반을 따로 기록한다.
- IQR 이상치 표시는 오류 확정이나 자동 삭제를 뜻하지 않는다. 유효한 고액 구매가 RFM에서 사라지지 않도록 오류와 정상적인 극단값을 구분한다. 구체적인 IQR 처리 전략은 다음 분석 단계에서 정한다.

## 8. 이미지 연결

- 46개 고유 상품명에 대표 스케치 46개가 연결되어 있다. 현재 파일 부재·상품명 미연결은 각각 0개다.
- `Product_Name`으로 매핑한다. 같은 이름이 실제 동일 모델이라는 보장은 없으며, 모델 단위 분석으로 확대 해석하지 않는다.
- 이미지는 AI 생성 합성 스케치다. 이미지 평균·표준편차는 피처 추출 구현을 보여주는 값이며 실제 상품 외관이나 구매 행동의 근거로 해석하지 않는다.

## 9. 구현 후 확인할 결과

원본/정제 행 수, 중복 제거 수, 표기별 매핑 수와 미매핑 값, 날짜 상태별 건수, 컬럼별 결측·대치 수, 숫자 오류 수, 상태별 포함·제외 수, RFM 대상 고객 수, 이미지 연결 누락 수를 보고한다. 모든 제외 건수는 처리 순서에 따른 중복 집계 여부를 구분한다.

전처리 구현은 아래 실행 명령으로 재현할 수 있으며, 월·일이 모호한 날짜에는 사용자 승인 국가별 가정을 적용한다. 규칙으로 해결할 수 없는 항목과 국가 규칙 충돌 항목은 확인 필요 목록에 남기고, 검토 후 재처리한다.


## 10. 실행 방법과 결과 파일

프로젝트 루트에서 프로젝트 가상환경을 사용한다.

```bash
.venv/bin/python src/pipeline.py
.venv/bin/python scripts/check_pipeline.py
```

입력·출력 경로를 바꾸려면 `--input 경로 --output-dir 경로`를 지정한다. 원본 디렉터리로의 저장은 거부한다. 같은 출력 디렉터리로 다시 실행하면 기존 정제 결과 파일을 갱신한다.

- `dataset/processed/transactions_cleaned.csv`: 완전 중복 제거 후 모든 상태의 거래. 원본 컬럼을 유지하고 정규화·대치·날짜 해석·분석 대상 표시를 파생 컬럼에 저장한다.
- `dataset/processed/review_required.csv`: 확인할 항목마다 한 행. 같은 거래에 여러 문제가 있으면 여러 행을 기록한다. 거래 식별은 `source_csv_row`로 하며 헤더 포함 CSV 레코드 번호다.
- `dataset/processed/preprocessing_summary.json`: 원본/정제 건수, 날짜 상태, 대치 단계, 상태별 분석 대상 건수 등을 기록한다. 중복 제거 수를 제외한 처리 집계는 중복 제거 후 기준이다.

`analysis_eligible=True`가 금액·RFM 공통 분석 대상이다. `analysis_exclusion_reasons`는 제외 사유를 세미콜론으로 연결한다. `row_needs_review`는 어떤 컬럼이든 확인 항목이 있는지 표시한다. 평점이나 국가 표기 등 분석 필수값이 아닌 문제는 확인 대상으로 남더라도 유효한 완료 구매의 금액·RFM을 일괄 제외하지 않는다.

국가 규칙 충돌 날짜는 `order_date_parsed`에 유효 후보를 남기지만 `date_needs_review=True`, `analysis_eligible=False`로 보류한다. `candidate_mdy`, `candidate_dmy`로 후보 해석을 비교할 수 있다. 파싱 실패·무한대·범위 밖 할인율은 그룹 대치로 숨기지 않고 확인 목록에 남긴다. 할인율은 원래 결측인 경우에만 대치한다.

이미지 피처·IQR 시각화·RFM 점수와 세그먼트·노트북 전후 비교는 후속 단계다. `detect_outliers()`는 삭제 없는 IQR 탐지, `calculate_rfm()`은 분석 대상 거래의 원시 R/F/M 계산을 제공하며 CLI 실행은 이 결과를 별도 저장하지 않는다.


### 실행 중 확인된 날짜 가정의 한계

중복 제거 후 국가 규칙과 충돌하는 날짜는 1,482행이다. 전체 숫자 날짜의 국가·구분자별 유효 해석 집계는 `preprocessing_summary.json`의 `country_separator_date_patterns`에 저장한다. 한쪽 해석만 유효한 날짜에서 `-`는 월/일, `/`는 일/월로만 유효한 패턴이 관측됐으며 반대 패턴은 관측되지 않았다. 이는 날짜 형식이 배송 국가보다 구분자와 연결됐을 가능성을 시사한다. 다만 월·일이 모두 유효한 날짜의 실제 의미를 확정하는 근거는 아니다.

현재 구현은 사용자가 승인한 국가별 가정을 유지한다. 충돌 날짜는 확인 목록에 남기며, 국가 가정으로 변환한 날짜도 확정 사실이 아니다. 실제 날짜 기반 인사이트를 확정하기 전 출처 확인 또는 다른 해석 시나리오와의 비교가 필요하다. 구분자 규칙으로 자동 변경하지 않는다.
